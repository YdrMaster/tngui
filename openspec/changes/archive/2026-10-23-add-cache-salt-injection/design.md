# Design

## Context

动机见 `proposal.md`。现有实现与约束决定了做法：

- `tngui-core/src/proxy.rs` 的 `handle_conn` 顺序固定：读头与体（>10 MiB → 413）→ 精确 `GET /v1/models` 直连 capi → 解析 `body.model` 生成 pre-TNG path（非法/缺失 → 400）→ 改头 → 转发内部 ingress → 逐字节回传响应。
- 目前请求体按字节原样转发，多个测试直接断言转发体与原体相等。
- 反代无本地会话、无后台任务；`ProxyDiagnosticsSnapshot` 是固定类别计数，明确不含动态 label。
- GUI 自身的推理请求也发往反代对外端点，因此加盐只在反代实现，`inference.rs` 不需要改动。
- 设置缓存是 `app_data_dir/settings-cache.json`，形状 `{schemaVersion:1, tng:{configJson, apiKey, rvsUrl}}`；Rust 侧只校验信封，不解析业务与凭据字段；前端负责解释与恢复。
- 盐必须在进入链路加密前写入请求体顶层，且不得进入请求头与任何可观测数据。

## Goals / Non-Goals

**Goals:**

- 三个推理端点默认注入顶层 `cache_salt`，可关闭；无盐请求照常处理。
- 盐支持关闭、固定值、自动刷新随机值三种模式，默认自动、每 30 分钟刷新。
- 覆盖开关默认不覆盖：只在缺少 `cache_salt` 时注入。
- 盐不进入请求头、日志、错误详情与诊断快照。
- 配置随设置缓存持久化，改动即时生效且不触发 tng 重启。
- body 改写保持最小侵入，不破坏既有 `body.model` path 注入与失败路径。

**Non-Goals:**

- 不实现服务端加盐、校验或拒绝逻辑。
- 本变更不提供按请求、按会话、按用户或按调用者的盐粒度；反代每次注入一个当前生效的盐。
- 不修改 tng 配置、远端授权或路由，不链接任何 tng crate。
- 不改变 `x-model` 语义，不新增 `x-model`。

## Decisions

### D1 注入位置：模型解析之后、转发之前

在 `resolve_model_path` 成功之后、设置 `Content-Length` 之前注入。此时请求体已被解析为合法 UTF-8 JSON object 且 `model` 是非空字符串，注入不需要再处理非法 JSON；非法/缺失 `model` 的 400 与超限 413 判定保持原样，`GET /v1/models` 直连分支在注入之前就已经返回。

备选是把注入放在读体之后立刻做：被否决，因为它会要求对未验证的 body 做修复式处理，也会让失败路径的判定顺序变得难以说明。

### D2 改写策略：首个 `{` 之后插入一个成员

只在顶层 object 的首个 `{` 之后插入 `"cache_salt":"<值>",`，其余字节、字段顺序、空白与转义保持不动。

备选是用 `serde_json::Value` 解析后整体重序列化：被否决——默认的 `serde_json` map 会按 key 排序，并归一空白、转义与数字表示，等于重写整个 body，与“尽量保留原字节”冲突，且会让所有既有断言 body 等价的测试失效。

判定“是否已有 `cache_salt`”复用模型解析已经得到的 `Value`，避免重复解析。需要改写时用 `serde_json` 只把盐值编码成带引号的转义字符串。

### D3 注入条件：按模式与覆盖开关决定

- 模式为关闭：不注入，body 逐字节不变。
- 已有顶层 `cache_salt` 且覆盖开关关闭：不改写，body 逐字节不变。
- 已有顶层 `cache_salt` 且覆盖开关开启：替换该成员为当前配置盐。
- 不存在顶层 `cache_salt`：注入当前配置盐。

覆盖关闭时用“缺席才注入”而不是“先删后加”，既尊重调用侧已写的盐，也让直连客户端能自选粒度。

### D4 自动盐：进程内随机、按周期惰性轮换

自动模式在反代会话内生成一个随机盐，并记下生成时刻；每个请求比较当前时间与生成时刻，超过刷新周期就生成新的随机盐再使用。轮换按请求触发，不另起后台任务——反代本来就无本地会话与后台任务，惰性轮换与之保持一致，可观测点也只在请求时刻。盐随反代生命周期存在：反代重启（tng 重启）即换新盐，与诊断快照的重置边界一致。

盐用 128 位随机数编码为十六进制字符串。

备选一是后台定时器：边界更整齐，但要多管理一个随反代启停的任务，收益不足以抵消复杂度。备选二是 `salt = H(seed, 时间桶)`：无状态，但需要可用的带密钥哈希，反而要多引入依赖或另给种子建模，不如直接重新取随机值直接。

### D5 随机源：新增一个跨平台依赖

现任依赖中没有随机数来源。选择新增 `getrandom`：接口单一、体积小、unix 与 windows 都走系统 CSPRNG。备选是复用 `std::collections::hash_map::RandomState` 的进程级种子：可行但属于借哈希器的实现细节，语义不够直白，不作为安全值的来源。

### D6 配置承载与即时生效：共享句柄 + 一条配置命令

盐策略放在 `AppState` 持有的共享句柄里，`start_proxy` 接收同一句柄，每个请求读取当前策略。前端在启动恢复设置后、以及用户在卡片上改动盐配置时，调用一条新的 Tauri 配置命令把模式/周期/固定值/覆盖开关推给 Rust。这样改动即时生效、不需要重启 tng。

保持“Rust 不解析设置缓存 payload”的现状：盐配置由前端从缓存读出来再推送，Rust 只接收已解释的字段。

备选是让反向代理在启动时读一次配置：实现更少，但用户改了配置要么不生效、要么被逼着重启 tng，与“即时生效”的要求不符。

### D7 持久化：设置缓存里加一个字段，不动 schemaVersion

在设置缓存的 `tng` 段下新增 `cacheSalt`，记录模式、刷新周期、固定值与覆盖开关。字段缺失或非法时回落默认值（自动、30 分钟、不覆盖）。不提升 `schemaVersion`：现有前端在 `schemaVersion !== 1` 时会整份丢弃缓存，提升版本等于让升级用户丢掉已保存的 API Key 与 TNG 配置。自动模式当前的随机盐不落盘，GUI 重启即重新生成，这也让每次启动天然是一个新的缓存分区。

### D8 不泄漏

盐只进请求体。反代不打日志、不把盐放进错误详情，也不给 `ProxyDiagnosticsSnapshot` 增加承载盐值或动态标签的字段。自动模式的盐值不下发前端，界面上也不展示当前盐值。

### D9 界面落点与既有需求同步

盐配置作为“密态推理”功能卡里 API Key 之外的一组控件。这会改动几条既有需求，delta spec 里按 MODIFIED 处理：卡片不再“只承载 API Key”；卡片布局的留白口径要覆盖新增行；凭据持久化需求里“只保留一个 API Key 输入框”的措辞要放开；设置缓存内容要含盐配置。盐配置改动不计入 TNG 配置 dirty，也不触发 tng 重启。

## Risks / Trade-offs

- **固定盐可能被猜中** → 不强制最小长度或熵，但提供“生成随机固定值”的操作并在文案里说明固定值越弱、隔离越弱，把选择留给用户。
- **轮换造成周期性冷缓存** → 每次轮换后该分区的首批请求会 miss，命中率在周期边界短暂下降。默认 30 分钟是隐私与命中率的折中，在文档中说明。
- **全局单盐不隔离本机多个调用主体** → 同一 tngui 实例的所有请求共享一个分区。对单用户桌面可接受，作为已知边界写入文档。
- **既有测试断言 body 逐字节相等** → 测试用的反代路由默认盐关闭以保持既有断言，另加开盐的正反用例；`direct_client_body_is_identity_feature_invariant` 这类测试的语义需要按“盐是唯一允许的 body 增量”重述。
- **新增依赖** → 只加 `getrandom`，用于生成盐值，不引入其它运行时依赖。
- **重复解析开销** → 判定已有盐时复用模型解析的 `Value`，不额外解析整个 body。

## Migration Plan

- 无破坏性迁移：老缓存缺 `cacheSalt` 字段时按默认值启动；`schemaVersion` 不变，已有 API Key 与 TNG 配置不受影响。
- 回滚：把盐模式切为关闭即可让反代恢复逐字节转发；或回退代码，设置缓存中的多余字段会被忽略。
- 验证按 `docs/ant-codespace-testing.md` 在 chroot 内单线程运行。
