# Design

## Context

The current integration guidance is in `frontend/src/views/InferenceView.vue`. It renders an “AI 客户端接入” tab with dynamic gateway information, DeepSeek Client branding, four DeepSeek-specific setup steps, a text configuration preview, a cURL example, and a warning against using a cloud endpoint. The DeepSeek visual is generated by `.deepseek-mark` in `frontend/src/assets/theme.css`; there is no tracked DeepSeek screenshot file in the repository.

The supplied screenshot is currently at the repository root as `hermes-agent-config.png` and is untracked. The frontend already has `frontend/src/assets/`, and Vite can import bundled images directly from that directory.

Official Hermes documentation supports a “Custom endpoint” provider that points to any OpenAI-compatible `/v1/chat/completions` endpoint. The relevant tngui behavior already exposes the local reverse-proxy endpoint through `localEndpoint` and uses a model ID obtained from `/v1/models`; this change must reuse those existing sources rather than introducing a second endpoint or model source.

## Goals / Non-Goals

**Goals:**

- Replace the client-specific guide with a Hermes Agent guide without changing actual inference, authentication, model discovery, proxy, or remote-attestation behavior.
- Keep all examples derived from the same local endpoint and selected-service model state already used by the page.
- Bundle the configuration screenshot as a versioned frontend asset and render it responsively.
- Keep the page layout readable in the application’s current minimum window size.

**Non-Goals:**

- Do not add Hermes runtime integration, install Hermes, launch Hermes, or manage Hermes processes from tngui.
- Do not alter Tauri commands, TNG configuration JSON, the reverse proxy, model discovery, streaming inference, or API-key handling.
- Do not introduce a dependency or fetch external images at runtime.
- Do not provider deeper Hermes configuration coverage beyond the custom endpoint path needed to reach the local TNG API.
- Do not preserve a DeepSeek-specific guide alongside the new Hermes guide.

## Decisions

### 1. Keep the integration guide inside `InferenceView.vue`

The change is a presentation-layer replacement inside an already isolated tab. It does not warrant a new routing boundary or a new feature component.

*Alternative:* extract an `IntegrationPanel.vue` component. This would better isolate markup, but it adds a component and test surface for a single-panel replacement while `InferenceView.vue` already owns the tab’s dynamic endpoint and model state. A future extraction can be made independently if this tab grows.

### 2. Replace only the DeepSeek-specific computed preview

Replace `deepSeekClientConfig` with a `hermesAgentConfig` computed value. It should generate the official Hermes custom-endpoint shape:

```yaml
model:
  default: <Model ID>
  provider: custom
  base_url: <API Base URL>
  api_key: <从 1 号节点控制台获取>
```

The values must continue to come from the existing computed sources:

- `base_url` from `localEndpoint`
- model value from the current `/v1/models` state and selected model
- API key only as a placeholder in the example; never emit the real API key

This avoids duplicate source-of-truth logic. Empty, loading, and failed discovery states should use the same visible textual state as the existing model preview.

*Alternative:* show a static tutorial screenshot only and omit a textable config example. That would reduce maintenance but make the guide non-copyable and prevent dynamic endpoint/model alignment.

### 3. Move the screenshot into `frontend/src/assets/`

Move the root-level `hermes-agent-config.png` to:

```text
frontend/src/assets/hermes-agent-config.png
```

Import it from `InferenceView.vue` with a bundled asset import and render it through a normal `<img>` element with descriptive alt text. The image should use `max-width: 100%`, automatic height, a bounded maximum height, and preserve its aspect ratio so the 3024×1706 image remains readable without forcing horizontal scrolling.

*Alternative:* place the file under `frontend/public/`. That would work for Vite, but the repository currently has no public asset directory, would produce a stable unhashed route, and would make the component less explicit about its dependency. `src/assets` also keeps the guide and its screenshot versioned together.

### 4. Use a simple Hermes “H” visual mark rather than fetching a remote logo

Replace `.deepseek-mark` with a Hermes-specific mark or heading treatment using the existing visual language. The official homepage link carries the authoritative brand destination; the section does not need to load third-party branding or depend on network access.

*Alternative:* download an official Hermes logo. That introduces an additional asset and license/branding review without being necessary for the integration task.

### 5. Link to the official Hermes page with safe external-link attributes

Use an explicit anchor for `https://hermes-agent.nousresearch.com/` with:

```text
target="_blank"
rel="noopener noreferrer"
```

Open the site in the user’s browser and give Hermes documentation authority over product details. This avoids embedding long, version-sensitive marketing copy in the application.

### 6. Treat the screenshot as documentation, not configuration state

The screenshot should visually support the custom endpoint setup but must not be parsed or used to change the generated config example. The textual example stays dynamic so the UI cannot become inconsistent with the selected endpoint or model.

*Alternative:* make the screenshot the only instruction. Rejected because it cannot update with the active local port and model ID.

## Risks / Trade-offs

- [Screenshot becomes stale as Hermes changes its UI] → Label it as a configuration example and retain the dynamic text steps plus official homepage link.
- [Screenshot could accidentally expose a real key or private data] → Review the supplied image before committing and ensure only placeholders or harmless example content are visible.
- [Hermes branding wording may drift] → Keep the embedded description short and factual, and link to the official homepage rather than copying detailed product claims.
- [Large image may affect bundle size] → The supplied PNG is approximately 312 KB, which is acceptable for a frontend bundle; Vite should fingerprint and cache it. Do not load it externally or introduce an image CDN dependency.
- [Narrow application windows could clip the screenshot] → Render it responsively with constrained maximum dimensions and allow vertical scrolling within the existing page layout.
- [Two model representations could diverge] → Reuse the existing local endpoint and model state computed values; do not create a separate model-specific variable for the Hermes example.

## Migration Plan

1. Move the supplied screenshot to the frontend assets directory during implementation.
2. Replace the DeepSeek-specific markup, computed preview, style, tests, and documentation in one frontend change.
3. Run the existing frontend typecheck and component test suite.
4. There is no persisted configuration, schema, or runtime migration because the change affects only static guidance text and an image asset.
5. Rollback consists of reverting the affected frontend and docs files; there is no stored data to migrate back.
