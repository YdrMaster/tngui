## Context

结构化编辑器中反代对外端口已有上下限，但远端端口输入没有一致边界；前端模型又把部分空/无效值折叠成默认值或省略 `port`，后端启动前也未完整校验端口范围。用户可通过原始 JSON 或导入绕过控件，因此校验需要在模型边界和后端扭转，不能只加控件属性。

## Goals / Non-Goals

**Goals:**

- 用一个统一端口校验规则覆盖三类用户端口：`tngui_outward.port`、mapping `out.port`、http_proxy `dst_filters.port`。
- 让“留空”成为唯一的“不限定目标端口”表达方式；显式 `0` 不再具有兼容含义。
- 保证导入、原始 JSON 回填和启动路径看到同一规则，避免 UI 只防正常路径。

**Non-Goals:**

- 不新增端口白名单、特权端口限制或可用性预检。
- 不改变自动注入的 TNG 内部端口、管控端口选取方式。
- 不改动远端 host 校验、远端默认端口、multi-ingress 或反代转发逻辑。

## Decisions

**1. 端口域定义为整数 `1~65535`，并区分必填与可选。**

- 反代对外端口和 mapping 远端端口必填：缺失、空、`0`、小数、负数、`>65535` 都在启动前报错。
- http_proxy 目标端口可选：留空/内部模型无值时省略 `port`；显式值必须通过同一端口域校验。
- 备选是仅给 InputNumber 添加 min/max。否决：原始 JSON、导入和后端仍会绕过，且旧代码可能把无效值折叠成默认值。

**2. 前端模型引入显式端口有效性判定，而不是继续用 `0` 或越界值表示省略。**

- 空目标端口统一表达为可选端口为空；序列化时直接省略 `dst_filters.port`。
- 必填端口不再在序列化时静默回填默认值；默认值只保留在初始化/切换形态/导入缺失时的表单回填场景。
- 备选是序列化时自动把非法值换成默认。否决：静默改写会让用户以为配置成功连接的是原目标。

**3. 后端在启动前执行独立端口校验。**

- 后端校验 JSON 中的三类端口，避免恶意构造或另一个前端的配置触发 `u16` 截断、绑定端口 0、转发到端口 0 等模糊失败。
- 错误消息包含 ingress 序号和字段位置，便于高级 JSON 用户定位。
- 备选是让 InputNumber clamp 后依赖 TNG 自身校验。否决：错误延迟到运行期，且 outward 端口由 tngui 自身消费，不都属于 TNG 校验。

## Risks / Trade-offs

- **[BREAKING：旧 JSON 显式 `port: 0`]** 以前可能被前端省略，现在导入/回填会失败。→ 迁移是删除该字段以表达“不限定端口”，错误消息可说明这一点。
- **[必填端口被误清空]** 用户可能清空 mapping 端口后直接启动。→ 启动前明确报错，而不是回填 `80` 掩盖意图。
- **[UI 控件差异]** 不同 WebView 对数值控件失焦行为可能不同。→ 模型级和后端级校验兜底，不依赖控件 clamp。

## Migration Plan

先加端口有效性工具与测试，再改前端输入/模型规则并在可视输入挂接边界，再接入后端启动前校验。旧配置若仅省略 `http_proxy.port` 仍兼容；显式 `0`/越界端口需删除或改为有效端口。回滚只需恢复端口处理与校验提交，数据格式本身没有新增持久化结构。
