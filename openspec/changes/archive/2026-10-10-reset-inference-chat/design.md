# Design

## Context

`InferenceView.vue` 已经把 `messages`、`draft`、`activeAssistantId`、`sending`、模型配置、思考强度和身份注入作为页面进程内状态管理。多轮请求通过现有 `buildRequestMessages(messages)` 从对话历史生成上下文。当前实现没有上下文重置边界，因此用户只能让后续请求继续携带全部已完成历史。

本变更沿用现有视图级状态，不引入新后端接口或持久化数据。本变更同时将应用发布版本推进到 `0.4.9`，并把 Cargo workspace / Cargo lockfile 与 frontend npm package 元数据保持在同一版本。

## Goals / Non-Goals

**Goals:**

- 提供明确的“重置”入口，只切断下一次及后续请求的旧上下文。
- 保留完整 UI 聊天轨迹，便于对照多次验证结果。
- 用可见“新对话”分隔线区分上下文边界，并允许在两次重置之间有新对话时再次插入。
- 防止在活跃推理流存在时修改 turn 集合，避免迟到 delta 或完成回调操作已移除的 assistant turn。
- 保持调试参数和未发送草稿不丢失。
- 将应用版本元数据统一推进到 `0.4.9`，避免发布标识滞后。

**Non-Goals:**

- 不实现对话历史持久化、导入、导出或恢复。
- 不清空模型发现状态、选中模型、思考强度、身份注入提示词或页面选项卡。
- 不改变现有“停止”请求的后端取消语义。
- 不增加系统级确认弹窗。

## Decisions

- **保留历史，只追加边界：** 重置动作不清空 `messages`，而是在当时消息末尾追加一个 UI 专用 `conversation-boundary` 项。这样旧对话仍可用于对照，也能在后续过程中再次重置并形成多次边界。

- **用最近边界切割上下文：** `buildRequestMessages` 需要定位最后一条边界项，只处理其后的 user 和完整的 assistant 消息；边界项本身必须始终被忽略。这样重置后的第一轮自然从新对话开始，后续多轮仍能保留新上下文。

- **可用性基于边界后的新消息：** 按钮可用条件是最近边界之后存在至少一条 user / assistant 消息且当前无进行中请求。空对话不可重置；刚重置但尚未开始新对话也不可重复重置，避免无意义分隔线。

- **发送路径与边界状态互斥：** 由于活跃 turn 必须保持稳定，重置按钮在 `sending` 时禁用。用户先停止并获得 failed/stopped 终态后，该终态 turn 会留在旧边界上方，随后可以重置。点击重置不调用后端取消接口。

- **按钮样式与放置：** 输入框左侧使用红色文字按钮“重置”，与右侧圆形发送/停止按钮形成方向区分；不使用“清空对话”这类与实际行为不符的文案。

- **版本推进随本变更合并：** 不单独创建 bump 变更；版本号只作为本变更的发布元数据，不新增版本展示或运行时行为。

## Risks / Trade-offs

- [上下文边界可能被误当作聊天消息发送] → 类型化边界项并在构建请求上下文时忽略；测试直接断言 reset 后请求只携带新轮次。
- [保留全部历史会让 UI 继续增长] → 设计优先满足用户明确要求：保留调试轨迹而不是隐藏历史；页面已有固定高度滚动容器承载增长。
- [多次边界可能造成视觉噪声] → 只有存在边界后新对话时允许再次重置；分隔线使用低对比度样式，仅保留“新对话”提示。
