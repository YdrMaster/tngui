# Spec Delta

## ADDED Requirements

### Requirement: 密态推理对话上下文重置

系统须（SHALL）在密态推理页聊天输入框左侧提供红色“重置”按钮。按钮仅在最近一次重置边界之后存在至少一条用户或 assistant 消息且没有进行中推理请求时可交互。点击“重置”须（SHALL）保留当时全部聊天消息，在消息流末尾插入一条新的重置边界，使下一次发送的请求上下文不再包含该边界之前的任何用户或 assistant 历史。系统不得（MUST NOT）重置模型清单、选中模型、思考强度、身份注入设置、未发送输入草稿或页面选项卡，不得（MUST NOT）为重置弹出现成确认对话框，也不得（MUST NOT）因重置把对话状态写入文件。

#### Scenario: 空对话禁用重置

- **WHEN** 密态推理页聊天区域没有用户或 assistant 消息
- **THEN** 聊天输入框左侧的红色“重置”按钮可见但不可交互

#### Scenario: 无新对话禁用重复重置

- **WHEN** 最近一次重置边界之后没有新的用户或 assistant 消息，即使边界前仍保留历史
- **THEN** “重置”按钮保持不可交互，不会连续插入新的边界

#### Scenario: 有新对话且空闲时允许重置

- **WHEN** 最近一次重置边界之后存在至少一条用户或 assistant 消息 AND 没有请求处于非终态
- **THEN** “重置”按钮可交互并显示为红色文字按钮

#### Scenario: 进行中请求禁用重置

- **WHEN** 当前 assistant 轮次处于阶段动画、流式接收或其他未终态
- **THEN** “重置”按钮不可交互；用户须先通过既有“停止”动作使本轮进入终态，才能点击“重置”

#### Scenario: 重置保留 UI 历史并切断上下文

- **WHEN** 用户在存在已完成历史轮次的对话中点击“重置”，随后发送新的用户输入
- **THEN** 既有用户与 assistant 消息继续按原状态显示；“重置”动作在消息流末尾插入“新对话”分隔线；下一轮请求 `messages` 只包含该新用户输入，不包含重置前的用户或 assistant 上下文

#### Scenario: 重置保留调试参数

- **WHEN** 用户点击“重置”
- **THEN** 模型、模型清单、选中模型、思考强度、身份注入状态、未发送输入草稿和页面选项卡保持重置前状态

### Requirement: 新对话分隔提示

系统须（SHALL）在每次成功重置后在当前消息流末尾显示一条低对比度分隔线，并在分隔线上居中显示“新对话”提示。历史消息须（SHALL）保留在分隔线上方，新的 user / assistant 消息须（SHALL）在该分隔线下方继续按时间顺序渲染。分隔提示是 UI 专用标记，系统不得（MUST NOT）把它渲染为普通聊天消息、发送给模型或计入后续请求上下文。

#### Scenario: 重置后立即显示分隔提示

- **WHEN** 用户点击可交互的“重置”按钮
- **THEN** 既有聊天消息继续显示，消息流末尾展示低对比度分隔线，分隔线上居中显示“新对话”提示

#### Scenario: 新消息渲染在分隔线下方

- **WHEN** 用户重置对话后发送新消息
- **THEN** 新 user / assistant 消息按正常聊天气泡渲染在最新分隔线提示下方；模型请求上下文只包含该分隔线之后的有效轮次

#### Scenario: 间隔新对话后可多次插入

- **WHEN** 用户先重置、在分隔线后完成或停止新一轮对话，然后再次点击可交互的“重置”
- **THEN** 每次重置都在当时消息流末尾新增一条分隔线；早期分隔线和历史消息继续保留
