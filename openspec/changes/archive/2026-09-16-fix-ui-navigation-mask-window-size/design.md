## Context

前端导航由 `App.vue` 通过 `provide("navigate", goTo)` 分发给子视图；概览页已使用该回调切换到设置页，密态推理页却把“前往设置”绑定到 `message.info`。设置页 API Key 通过 `useInferenceConfig().apiKey` 保存为会话内存态，当前用普通 `a-input` 渲染。入口信息卡是纯配置摘要，但组件内部额外渲染了一个带灰色圆点的状态行。桌面窗口尺寸在 `tauri.conf.json` 中为 900×720，全局 CSS 的内容最小宽度为 1180px，两者之间的矛盾是默认状态出现横向滚动和卡片退化排布的直接原因。

## Goals / Non-Goals

**Goals:**
- 统一“前往设置”为视图切换动作，不使用提示弹窗替代导航。
- 用适合 Ant Design Vue 的密码输入组件实现默认遮盖和用户主动显隐，维持凭据不入配置。
- 删除入口信息卡的伪状态行，恢复只读配置摘要语义。
- 在 Tauri 窗口配置中建立更大的默认尺寸和明确的可缩窗口下限。
- 降低全局与设置表单的横向/纵向最小占用，使默认概览在一屏内可读。

**Non-Goals:**
- 不更改 `useInferenceConfig` 的存储位置、生命周期或序列化路径。
- 不改变 tng 启动流程、远端 IPv4 校验、状态判定或反向代理契约。
- 不为了完全塞下所有设置内容而压缩到不可读；设置页长内容允许纵向滚动。
- 不新增数据库、进程管理或新的导航中间件。

## Decisions

- **导航复用 `navigate` 注入：** 密态推理页的按钮改为调用与概览页相同的 `navigate("settings")` 动作。删除按钮专属的 `message.info`。这样导航入口只有一个来源，避免后续两种“前往设置”行为分叉。备选方案是在按钮内直接操作路由或全局 store；当前应用无路由且已有单一 `goTo` 通道，引入新机制没有必要。
- **API Key 使用组件级密码输入：** 将 `a-input` 改为 `a-input-password`，默认遮盖并使用其显隐按钮。绑定仍指向 `apiKey` ref；`apiKey` 不进入 `serializeCurrent()`，因此遮罩不影响配置写盘。比手写输入类型/切换状态更简单，并保持同一输入框内的显隐交互。
- **入口信息卡删除状态行：** 直接移除 `IngressInfoCard.vue` 中的圆点与“仅配置摘要”行，让 slot 中的三行成为卡内首组内容。现有 `ingress-state-home` 规格已要求入口信息卡不使用状态色点，这次是修正实现偏差，不需要新增规格。
- **窗口尺寸集中配置在 Tauri：** `tauri.conf.json` 的桌面窗口设置为 `width: 1440`、`height: 960`、`minWidth: 1120`、`minHeight: 720`。使用逻辑像素尺寸由 Tauri 处理 DPI，避免前端再探测屏幕或在运行时调整窗口。备选方案是在应用启动后调用窗口 API，但会引入首帧跳变和 async 失败处理。
- **布局密度分三类收敛：** 先把全局内容最小宽度降到 1120px 并将外层留白变紧；再压缩入口编辑器中的固定/最小列宽，使远端类型、IP/域名、端口和 verify 字段在较小内容列内换行而不是撑出滚动；最后降低 JSON 编辑区与若干展示面板的最小高度。不使用全页面缩放，因为会影响文字可读性和控件语义。

## Risks / Trade-offs

- [默认 960 高度在小物理屏幕上可能超过工作区] → Tauri/OS 会夹紧窗口，1120×720 的最小布局保证夹紧后仍可用。
- [密码组件的自带眼睛图标增加宽度] → API Key 卡片为单控件纵向布局，1440 默认宽度下不构成截断；如最大级别紧凑模式触发，可让输入区占满卡片宽度。
- [压缩固定列宽后右对齐数字控件更窄] → 只将端口、verify 等短值控件降到仍可输入的宽度；IP/域名等长文本继续使用弹性宽度并可换行。
- [无头/静态测试难以断言 Tauri 原生窗口] → 通过读取窗口配置 JSON 做确定性检查，另用前端布局检查和默认配置概览的视觉验证兜底。
