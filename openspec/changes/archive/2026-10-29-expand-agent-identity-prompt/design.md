# 设计

## 背景

身份提示词由 `frontend/src/views/InferenceView.vue` 的 `DEFAULT_IDENTITY_PROMPT` 提供，默认开启；发送时生成一次快照，`对话模式` 把它作为 `messages[0]` 的 system 消息，`Agent 模式` 把它作为 rpi harness 的 `system_prompt`。两种模式已经共用同一段文本，注入链路无需改动。当前主规格 `gui-shell` 中缺少身份提示词注入要求，本变更需要以新增要求的形式补回。

## 目标 / 非目标

**目标：**

- 用一段共用默认文案让模型正确理解“模型推理在 TEE 内、Agent 编排与本地工具在用户终端 TEE 外”的双边界。
- 为缺少相关背景知识的模型补充 TEE、TNG 与远程证明链路的概念。
- 恢复并更新 `gui-shell` 对身份提示词注入的持久规格覆盖。

**非目标：**

- 不改变身份注入的开关、编辑、快照、逐字注入或非持久化语义。
- 不新增 Agent 模式常驻 UI 安全提示。
- 不引入具体 TEE 厂商、证明后端或链路协议名。
- 不修改后端命令、事件、反代或 TNG 配置。

## 决策

### D1 两种模式共用一段默认文案

沿用现有单文本注入路径，不按运行模式动态拼接身份段落。

- **理由**：现有代码已经共用同一 `systemPrompt`，单文本不会破坏发送时快照、逐字注入和页内状态语义；文案用“Agent 模式下”限定工具能力，足以覆盖两种模式。
- **备选**：在 Agent 模式自动追加安全段。否决：会让编辑区内容与实际注入内容不一致，增加状态和测试分支。

### D2 概念说明停留在原理层

补充 TEE、TNG、远程证明时只解释隔离执行、链路转发、对端验证和验证失败阻断，不写具体硬件型号、证明服务实现或协议名。

- **理由**：模型可能缺少世界知识，需要的是可迁移的概念；具体实现信息容易过时，也会违反现有“不得虚构实现细节”的约束。

### D3 不新增 UI 常驻安全提示

安全提醒只写入默认身份提示词。用户关闭注入或改写文案时，视为已知后果。

- **理由**：用户已明确接受该边界；UI 不新增额外警示控件，保持现有工具栏不变。

### D4 以新增要求补回 `gui-shell`

当前主规格没有身份提示词注入要求，delta 使用新增要求，并按控件、默认文案、注入语义、状态与作用域拆成四个要求。

- **理由**：避免去修改一条不存在的要求；拆分后每个要求只描述一类行为，也满足描述长度校验。

## 风险与取舍

- **[提示词变长，增加 token 消耗]** → 文案控制在必要概念和边界内，不展开协议细节。
- **[模型仍可能把本地工具误认为受 TEE 保护]** → 文案明确区分 Agent 本地执行与模型推理，并用“工具数据、参数与结果不受 TEE 保护”单独说明。
- **[用户关闭或改写注入后失去安全提醒]** → 这是用户明确接受的行为，不在 UI 层额外补偿。
- **[规格与实现再次漂移]** → 本次以 delta 补回 `gui-shell` 要求，并在任务中要求严格校验与归档后核对。

## 迁移计划

纯文本、版本与规格变更，无数据迁移。回滚时恢复旧默认提示词、旧版本号，并撤回对应规格、测试和文档改动即可。
