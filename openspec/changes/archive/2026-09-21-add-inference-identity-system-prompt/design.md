# Design

## Context

- 当前“密态推理调试页”的请求上下文只包含已完成 `user` / `assistant` 消息，模型思考强度和模型选择都已经作为页内状态保留。
- `InferenceRole` 在现有契约里只允许 `user` / `assistant`，系统没有现成 `system` 入口。
- 反向代理当前只解析 `body.model` 并改写请求路径，请求 body 字节原样透传。
- 推理页已经通过 KeepAlive 保留页内状态，并且不需要落盘迁移。
- 现有最小窗口宽度为 `1120px`，模型控制区与思考强度控制区之间仍有可用空间放置身份注入控件。

## Goals / Non-Goals

**Goals:**

- 让调试页能明确把“蚂蚁密算 + 可信执行环境 + 远程证明”的身份系统提示词注入给模型。
- 保持 `user` / `assistant` 聊天历史契约不变，把身份注入当成一个独立的调试上下文字段。
- 保证直接进入反向代理的请求与通用客户端接入行为完全不被本功能影响。
- 做一个默认开启、可控关闭、可编辑的调试辅助，不新增持久化边界。

**Non-Goals:**

- 不把该提示词写入设置页、设置缓存、TNG 配置或 `tng-runtime.json`。
- 不新增独立调试端口或专属反向代理。
- 不为该身份注入新增鉴权、租户或多用户概念。
- 不把身份提示词渲染为普通聊天消息或写进对话历史推导。

## Decisions

### 1. 身份注入放在调试页调用层，而不是反向代理

采用的路径是：

```text
密态推理调试页
   |
   | 是否开启注入 -> 取当前身份提示词
   v
send_inference_stream
   |
   | 组装 [system] + [user / assistant ...]
   v
本机反向代理
   |
   | body.model -> path 注入
   v
TNG
```

直接外部客户端保持：

```text
外部客户端 -> 本机反向代理 -> TNG
```

**理由：**

- 只有调试页明确知道“要不要注入身份”。
- 反向代理无法可靠区分请求来自调试页还是外部客户端，一旦在代理层注入，通用接入就会被动改变。
- 反向代理继续保持 body 原样透传，能把“调试辅助”与“通用网关行为”严格隔离。

### 2. 身份提示词作为独立 system 参数，而不是扩展聊天历史角色

实现时把身份注入建模为调试页发送层的一个独立 `systemPrompt`，而不是把现有 `InferenceRole` 扩展成通用的 `user / assistant / system` 三态。

**理由：**

- `user` / `assistant` 继续表示聊天历史本身，语义清晰。
- 身份提示词不是用户输入，也不是聊天轮次，不应进入对话状态推导。
- 独立参数让“调试页专用 system 注入”和“通用 messages 数组”在代码结构和测试上都不混淆。

### 3. 默认开启，编辑框独立展开

- `identityPromptEnabled` 默认 `true`。
- `identityPrompt` 默认为内置详细提示词。
- `identityPromptEditorOpen` 默认 `false`。
- 点击“编辑身份”时切换编辑框展开状态。
- 发送时一次性读取当前开关和文本，作为本轮 `systemPrompt` 传下去。
- 已发出请求不监听后续 UI 状态变化，因此自然满足“只影响下一次发送”。

### 4. 编辑框作为固定宽度浮层，避免挤压聊天记录

- 新增身份控件组仍放在顶栏中部，不改变现有 `200px` 模型控件与 `280px` 思考强度控件的基础布局。
- 编辑框使用固定 `480px` 宽度，`minRows: 4`、`maxRows: 12`。
- 超过 12 行后编辑框内部滚动。
- 弹出区域作为覆盖层显示，不嵌入正常文档流，也不压缩聊天记录高度。
- 顶栏内保持控件安全间距，确保 `1120px` 最小窗口宽度下不出现挤爆或溢出。

### 5. 身份提示词不进入现有推理页状态落盘链路

身份注入的三个状态都只留在推理页组件内存中：

```text
identityPromptEnabled
identityPrompt
identityPromptEditorOpen
```

由 KeepAlive 保证应用内页面切换时不丢失，GUI 进程退出后自然重置为默认值。该状态不进入设置缓存快照。

### 6. 编辑内容原样保留

为避免把身份提示词当成普通表单输入规范化，实现时：

- 不 trim。
- 不改大小写。
- 不折叠空行。
- 不做任何字符替换。

这与现有“用户 prompt 不得 trim”的精神一致。

## Risks / Trade-offs

- **[Provider 兼容性] 部分模型可能对 `system` role 处理不完全一致**：
  - 若服务端拒绝该消息，现有推理失败路径会正常暴露；不做自动降级成 `user`，因为那会改变系统语义。
- **[状态可见性] 身份提示词不出现在聊天 transcript 中，用户可能不知道当前轮是否携带**：
  - 通过“注入身份” toggle 的显式状态和可编辑面板补足可观察性。
- **[默认开启会改变调试请求内容]**：
  - 这是产品要求；用户可通过 toggle 关闭。反向代理和外部客户端不被影响。
- **[提示词长度影响 token 消耗]**：
  - 保持文案适中，不做完整版/精简版双模式，避免引入额外状态和测试分支。
- **[固定宽度面板对窗口尺寸敏感]**：
  - `480px` 在当前最小窗口和现有控件布局下有足够余量，不使用更宽的“半页”方案。
- **[编辑框是覆盖层]**：
  - 不压缩聊天区域高度，符合现有 transcript 高度稳定契约。

## Migration Plan

- 功能上线即默认启用身份提示词，没有历史数据迁移。
- 不涉及持久化结构或配置格式变化，因此无需升级设置缓存 schema。
- 现有反向代理和外部客户端接入不需要迁移。
- 若调试场景需要纯 OpenAI 原始请求，用户只需关闭“注入身份”开关即可回到无 system message 的请求形态。
