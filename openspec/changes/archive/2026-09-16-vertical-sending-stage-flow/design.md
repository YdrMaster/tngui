## Context

`SecureFlow.vue` 目前用一个横向 flex 容器渲染五个固定宽度节点，`InferenceView.vue` 在发送中同时渲染独立标题、说明、进度条和该横向流程条。因此响应卡内存在重复文案，横向节点也可能被截断。阶段文案来自 `secureSteps.ts`，阶段 2 已符合现有 OpenSpec 的 OHTTP/证明表述。

## Goals / Non-Goals

**Goals:**
- 将发送中的五步展示改为一个固定高度、固定宽度自适应的当前阶段卡。
- 阶段推进时形成旧卡向上淡出、新卡从下方淡入的连续转场。
- 用小圆点/序号提供流程位置，保留现有线性进度条。
- 保持减少动效偏好下的可用性。
- 不重复实现标题与说明：阶段卡就是标题/说明的唯一来源。

**Non-Goals:**
- 不改发送状态机、计时节奏、请求格式或响应处理。
- 不改安全说明页的静态架构图。
- 不增加动画库或外部依赖。
- 不把安全阶段展示绑到真实后端探针数据。

## Decisions

- **直接演进 `SecureFlow.vue`：** 该组件当前只服务于密态推理发送动画。将其从横向节点列表改为单卡阶段视图，可避免留下一个仅有一个入口的相近组件。
- **使用 Vue 内建 Transition：** 以阶段 key 触发 `enter/leave` transition，采用 `mode="out-in"`。CSS 用垂直位移与透明度即可满足方向性过渡，并保持零依赖。
- **固定视口高度：** 阶段轮播区域设定一个足够容纳图标、长说明和标题的固定/最小高度；转场元素绝对定位在视口内，避免内容长短不同导致高度跳动。
- **小阶段指示足关联：** 顶部五个小圆点只标记流程进度，当前点强调、已过点弱化；这不重新引入五张卡片，也不把说明文字再次列举出来。
- **减少动态效果回退：** 沿用项目已有 CSS 策略，在 `prefers-reduced-motion: reduce` 中把垂直 transform 和 transition 禁用，阶段按钮推进时内容直接替换。
- **复用现有安全文案：** 继续读取 `secureSteps.ts`，不重写阶段语义，避免与“建立加密通道”相关的既有规格冲突。

## Risks / Trade-offs

- [`mode="out-in"` 会让切换更像连续两段而非严格交叉淡化] → 更能保证不重叠、不跳动，也贴近“经过的卡先上移淡出”的预期。
- [固定高度过长会浪费响应卡空间] → 取当前单卡的最大内容高度并保持紧凑，不使用整个响应面板高度。
- [请求很快完成时用户可能看不到完整动画] → 不改变现有发送状态机；动画仍只覆盖发送中阶段，不延迟真实响应。

## Migration Plan

1. 将 `SecureFlow.vue` 改为单阶段卡组件，仅在发送中区域使用。
2. 更新 `InferenceView.vue` 中重复的阶段标题/说明与流程条布局。
3. 在全局主题中替换横向节点样式，为当前阶段、阶段点、转场和减少动效回退设置样式。
4. 以实际发送动作检查 0→1、1→2、2→3、3→4 的方向性切换和高度稳定。
