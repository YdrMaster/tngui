## Context

设置页当前拥有独立的 `pollStatus()` 和简化状态格子；密态推理页使用手写 prompt textarea 与 Ant Design 按钮默认排版；日志导出仍是占位提示。概览页已经有共享的 `useIngressState` 和三张状态卡渲染路径，可直接作为设置页同源数据来源。探索阶段已确认本次语义假设：“设置页失去焦点”按导航离开设置视图实现；自动保存只对真正成为 TNG 配置模型的变更静默保存。

## Goals / Non-Goals

**Goals:**
- 密态推理请求表单只做输入体验与局部排版精简，不改变请求协议。
- 设置页状态、凭据和保存交互保持简单、同源、可预期。
- 用原生保存对话框和后端已有进程日志快照完成真实日志导出。

**Non-Goals:**
- 不引入配置持久化、不改变 API Key 生命周期。
- 不改变 TNG 配置 JSON 结构、推理链路、自动重启条件或原始 JSON 编辑能力。
- 不重新设计概览“入口信息”卡或把入口信息复制到设置页。

## Decisions

### 1. 状态视图复用
用一个从 `IngressStates` 推导状态卡视图的共享 helper，供 Overview 和 Settings 使用；Settings 直接消费 `useIngressState()`。这样保证运行状态、远端链路、远端证明三张卡的标题、状态文本、副标题和颜色语义与概览一致，删除设置页独立的 `get_status ready` 摘要。

备选方案是复制概览的三组 computed 到 Settings。实现更快，但会再次产生状态语义漂移，不符合同源目标。

### 2. 密态推理表单细节
- prompt textarea 使用 `auto-size`，设置最小 4 行、最大 16 行，并禁用 resize；最大行数避免长 prompt 把页面无限撑高。
- 发送按钮改为 flex 对齐容器，图标行高为 1，保证与文字中线一致。
- 删除发送按钮下的锁形 alert，不再保留额外说明条。

### 3. 密态推理卡收敛
设置页保留“密态推理”卡和唯一 API Key 表单项；输入绑定到既有内存态，类型改为普通文本。移除密码遮罩、显隐按钮、状态说明、操作按钮和清除凭据区块。配置导入/导出仍保留在 TNG 配置区，不在密态推理卡内重复。

### 4. 自动保存入口
保留导航切换时的既有自动保存流程：离开设置视图时检查 dirty，dirty 则保存并按 TNG 当前状态决定是否重启；未 dirty 不动作。删除两个手动保存按钮和成功类提示。保存失败、启动失败、写入失败仍然显式提示，避免静默吞掉真实错误。

原始 JSON 视图继续通过“应用回填表单”进入配置模型；本次不把未回填的非法 JSON 自动写入 tng-runtime.json。

### 5. 日志导出
新增一个 Tauri 命令，从 supervisor 的 stdout/stderr 快照读取日志并写入用户提供的路径；前端只负责弹出原生另存为对话框、把取到的有效路径传给命令并展示失败。为与概览同源，导出数据不由设置页独立拼装，也不写入“（暂无输出）”占位文本。

备选方案是复用当前 JSON 导出命令并由前端传入日志字符串。这样可少加命令，但对话框过滤器和语义都会误导用户，也让日志内容来源经过前端转换。

### 6. 设置卡片与信息精简
- TNG 配置标题统一为“TNG 配置”。
- 生成状态卡和导出日志后，替换旧 Gateway 摘要格子；保留 TNG Gateway 区域内的导出日志操作。
- 客户端信息 descriptions 改为两列，只保留编译期得到的版本与操作系统。

## Risks / Trade-offs

- [用户把“失去焦点”理解成窗口失焦] → 在变更与文档中明确为从设置视图切到其他视图；不监听窗口 blur。
- [`auto-size` 上限与用户期望不一致] → 采用 4 到 16 行的有界区间；超长内容在框内滚动，避免影响右侧响应区。
- [删除成组设置控件后用户不知道哪里导入配置] → 导入/导出仍留在 TNG 配置区；密态推理卡不再承载配置操作。
- [导出目标路径冲突或不可写] → 保存失败立即显示错误，不修改原始日志和面板。

## Migration Plan

前端与 Tauri 命令一起发布即可。旧 UI 没有本地迁移状态；日志导出只是新增能力，配置和凭据生命周期不变。回退时恢复相关组件和命令绑定即可。
